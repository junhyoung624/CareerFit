## 1. 이력서 개인정보 · Gemini 무료 등급

**문제**

- 이력서에는 이름·연락처·경력 등 개인정보가 들어간다.
- Gemini API 무료 등급은 입력 데이터가 Google 서비스 개선에 사용될 수 있다는 조건이 있다. (정확한 조건은 Gemini API 약관에서 확인)
- 현재 계획에는 데이터 삭제·고지 관련 태스크가 없다.

**수정안**

- **W2-1** 프롬프트에 추가:
  ```
  업로드 화면에 "업로드한 이력서는 AI 분석에 사용됩니다" 안내 문구를 넣어줘.
  ```
- **W3-1** 프롬프트에 추가:
  ```
  LLM에 보내기 전에 이메일·전화번호 같은 연락처를 마스킹하는 함수를 lib/llm에 만들어줘.
  ```
- **W4-3** 점검 목록에 추가: 계정 삭제 시 모든 데이터(DB 행 + Storage 파일) 삭제
- **0일차**에 추가: `- [ ] Gemini API 약관에서 무료 등급 데이터 사용 조건 확인 → 실제 사용자 받기 전 유료 등급 전환 여부 결정`

**면접 포인트**: "개인정보를 어떻게 다뤘나요?" → 마스킹, 고지, 삭제, RLS

## 2. Vercel 배포를 1주차로 앞당기기

**문제**

- 배포가 W4-4에 있어, 배포 환경에서만 생기는 문제(환경변수 누락, Supabase Auth redirect URL, 서버 함수 시간 제한)를 마지막 주에 한꺼번에 만나게 된다.

**수정안**

- **W1-4 다음**에 새 태스크 추가:
  ```
  ### W1-6. Vercel 첫 배포
  - [ ] 완료
  GitHub 레포를 Vercel에 연결해서 배포해줘. 필요한 환경변수 목록(.env.example 기준)과
  Supabase Auth의 Site URL / Redirect URL에 배포 주소를 추가하는 방법을 알려줘.
  ```
  **완료 기준**: 배포 URL에서 회원가입 → 로그인 → 직군 선택 동작
- **W4-4**는 "첫 배포"가 아니라 "배포 점검 + 시드 데이터 + 스모크 테스트"로 이름 변경

## 3. 공고 URL fetch를 보조 경로로 낮추기

**문제**

- CLAUDE.md는 "크롤링 금지"인데, W2-4는 공고 페이지를 서버에서 가져온다. (1건, 사용자 요청 시라 성격은 다르지만 약관 확인 필요)
- 실제 공고 본문은 이미지·iframe인 경우가 많아 fetch가 실패할 가능성이 높다.
- 로켓펀치 Open API가 현재 공개 신청 가능한지 불확실하다.

**수정안**

- **W2-4** 프롬프트 수정: "붙여넣기 입력을 기본 경로로, URL fetch는 시도해보고 성공하면 미리 채워주는 보조 기능으로"
- **CLAUDE.md "공고 본문 확보 규칙"**에 추가: "fetch 전에 해당 사이트 이용약관·robots.txt 확인"
- **0일차**에 추가: `- [ ] 사람인 API 약관에서 원문 페이지 접근·표시 조건 확인`, `- [ ] 로켓펀치 Open API 신청 가능 여부 확인`

## 4. LLM 후처리 테스트 추가 (Vitest)

**문제**

- 계획 전체에 자동 테스트가 없다.
- "근거 없는 confirmed → needs_check로 내림" 같은 후처리는 이 프로젝트 신뢰성의 핵심인데, 동작을 증명할 수단이 없다.

**수정안**

- **W3-1** 프롬프트에 추가:
  ```
  Vitest를 설치하고, JobAnalysis / MatchResult zod 스키마 테스트를 작성해줘
  (정상 JSON 통과, 필드 누락·잘못된 status 거부).
  ```
- **W3-3** 프롬프트에 추가:
  ```
  후처리 함수 테스트: 근거 없는 confirmed가 needs_check로 바뀌는지,
  존재하지 않는 경험 id를 근거로 든 경우 처리되는지.
  ```
- 작업 방식(CLAUDE.md)에 `npm run test` 통과 확인 추가 (W3-1 이후부터)

**면접 포인트**: "AI 출력을 어떻게 믿을 수 있게 했나요?" → 스키마 검증 + 후처리 + 테스트로 증명

## 6. `analyses.status` 컬럼 · LLM 응답 시간 대비
